Base de Datos y Persistencia: persistence.xml y JPA

               
               
                   

La persistencia es el mecanismo que permite que los datos de una aplicación se almacenen de forma duradera, generalmente en una base de datos relacional. En Java EE y Jakarta EE, la tecnología estándar para lograrlo es la Java Persistence API (JPA), que se encarga de mapear objetos Java a tablas de la base de datos.


Conceptos clave

                   
                           
  • Entidad: Clase Java anotada con @Entity que representa una tabla en la base de datos.
    •                        
  • Unidad de persistencia: Configuración definida en persistence.xml que especifica el proveedor, la conexión y las clases gestionadas.
    •                        
  • ORM (Object-Relational Mapping): Técnica que mapea automáticamente clases Java a tablas SQL.
    •                        
  • Proveedor JPA: Implementación concreta de JPA, como Hibernate, EclipseLink u OpenJPA.
    •                    
                   

Configuración de Maven para Persistencia

                   

Para que Maven pueda manejar JPA, necesitas agregar las dependencias del proveedor JPA (como Hibernate) y el driver de la base de datos que estés usando (por ejemplo, MySQL Connector/J). Aquí está un ejemplo de cómo se vería la sección <dependencies> en tu pom.xml:


<dependencies>
    <!-- Dependencia de Java Persistence API -->
    <dependency>
        <groupId>org.hibernate.orm</groupId>
        <artifactId>hibernate-core</artifactId>
        <version>5.4.32.Final</version>
    </dependency>
    <!-- Driver de MySQL -->
    <dependency>
        <groupId>mysql</groupId>
        <artifactId>mysql-connector-java</artifactId>
        <version>8.0.28</version>
    </dependency>
</dependencies>
                   

Ejemplo de entidad JPA


import javax.persistence.*;

@Entity
@Table(name = "productos")
public class Producto {
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    private String nombre;
    private double precio;

    // Constructor vacío (requerido por JPA)
    public Producto() {}

    public Producto(String nombre, double precio) {
        this.nombre = nombre;
        this.precio = precio;
    }

    // Getters y Setters
}
                   

Archivo persistence.xml

                   

Este archivo de configuración se ubica en src/main/resources/META-INF/ y define cómo JPA se conecta a la base de datos. El transaction-type indica si las transacciones serán gestionadas por el contenedor (JTA) o manualmente por la aplicación (RESOURCE_LOCAL).


<?xml version="1.0" encoding="UTF-8"?>
<persistence version="2.2"
    xmlns="http://xmlns.jcp.org/xml/ns/persistence"
    xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
    xsi:schemaLocation="http://xmlns.jcp.org/xml/ns/persistence
    http://xmlns.jcp.org/xml/ns/persistence/persistence_2_2.xsd">

    <persistence-unit name="miUnidad" transaction-type="RESOURCE_LOCAL">
        <provider>org.hibernate.jpa.HibernatePersistenceProvider</provider>

        <class>com.ejemplo.modelo.Producto</class>

        <properties>
            <property name="javax.persistence.jdbc.url" value="jdbc:mysql://localhost:3306/midb"/>
            <property name="javax.persistence.jdbc.user" value="root"/>
            <property name="javax.persistence.jdbc.password" value="password"/>
            <property name="javax.persistence.jdbc.driver" value="com.mysql.cj.jdbc.Driver"/>

            <property name="hibernate.hbm2ddl.auto" value="update"/>
            <property name="hibernate.show_sql" value="true"/>
            <property name="hibernate.format_sql" value="true"/>
        </properties>
    </persistence-unit>
</persistence>
                   

Operaciones CRUD con JPA

                   

El EntityManager es la interfaz principal para interactuar con la base de datos. A través de él, puedes realizar las operaciones básicas de **Crear, Leer, Actualizar y Eliminar (CRUD)**. Aquí se muestra un ejemplo completo de un DAO que maneja estas operaciones:


import javax.persistence.*;

public class ProductoDAO {
    private EntityManagerFactory emf = Persistence.createEntityManagerFactory("miUnidad");

    public void crearProducto(Producto p) {
        EntityManager em = emf.createEntityManager();
        em.getTransaction().begin();
        em.persist(p);
        em.getTransaction().commit();
        em.close();
    }

    public Producto buscarProducto(Long id) {
        EntityManager em = emf.createEntityManager();
        Producto p = em.find(Producto.class, id);
        em.close();
        return p;
    }

    public void actualizarProducto(Producto p) {
        EntityManager em = emf.createEntityManager();
        em.getTransaction().begin();
        em.merge(p);
        em.getTransaction().commit();
        em.close();
    }

    public void eliminarProducto(Long id) {
        EntityManager em = emf.createEntityManager();
        em.getTransaction().begin();
        Producto p = em.find(Producto.class, id);
        if (p != null) {
            em.remove(p);
        }
        em.getTransaction().commit();
        em.close();
    }
}
                   

Buenas prácticas

                   
                           
  • Usar hbm2ddl.auto=update solo en desarrollo. En producción, manejar scripts SQL manualmente.
    •                        
  • Separar la capa de persistencia de la lógica de negocio.
    •                        
  • Controlar el ciclo de vida de EntityManager para evitar fugas de memoria.
    •                        
  • Utilizar transacciones para todas las operaciones que modifiquen datos.
    •                    
                   

Con JPA y Maven, puedes integrar fácilmente la persistencia de datos en aplicaciones Java EE, manteniendo el código limpio y escalable.
